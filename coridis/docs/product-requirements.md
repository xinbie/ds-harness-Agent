> 本版补充产品方向：**深度网络信息采集 + 结构化沉淀 + 事件逻辑归因**。
> 当前代码只是底座运行时（最小 Agent Harness），产品能力大多尚未实现；文中“已实现”仅指现有代码事实。

## 1. 背景与问题

用户往往只有一个模糊目标，例如“我想转行做 AI 应用工程师，需要具备哪些条件”，
或“帮我摸清新能源车企最近的招聘趋势”。从这个问题到可执行结论，中间隔着四道断层：

1. **采集断层**：信息散落在招聘站、公司官网、行业报告和社区中，人工收集慢且覆盖有限。
2. **结构断层**：网页是非结构化文本，岗位、技能、薪资、时间、公司等字段需要抽取和归一。
3. **资产断层**：一次性爬取的结果难以复用；换一个问题往往要从零再爬。
4. **归因断层**：看到“高频要求”不等于知道“哪些条件真正影响结果”，相关性与因果性容易混淆。

现有工具通常只解决其中一段：爬虫擅长采集但不做归因，分析工具依赖人工整理的数据，
通用 Agent 能调用工具但缺少可复用的数据资产与证据链。

## 2. 产品定位

### 2.1 一句话定位

一个把**模糊需求**转化为**可追溯数据资产**，并在此基础上完成**事件逻辑归因**与报告交付的 Agent 产品。

### 2.2 产品形态

- **定向研究**：用户给出明确目标（如岗位条件分析），Agent 完成澄清、采集、分析、归因、报告。
- **开放式采集**：用户只给出模糊需求，Agent 先协商范围与口径，再执行海量并发采集，沉淀为数据资产。
- **资产复用**：后续问题优先查询已有资产，只做增量采集。

两种入口共享同一套底座：Cordis 插件运行时、能力接缝、会话与证据日志。

### 2.3 目标用户

待确认。候选：

- 求职者与职业规划人群：需要知道目标岗位的真实门槛与优先条件。
- 招聘与人力资源研究：需要观察岗位需求、技能结构与薪资变化。
- 行业研究、投研与咨询：需要快速形成带来源的行业数据与结论。
- 需要定制数据集的业务团队：希望把采集结果沉淀为可查询资产。

### 2.4 核心价值

- **从模糊到可执行**：把“帮我看看”拆成采集计划、字段口径、分析问题与交付物。
- **证据可追溯**：每条结论都能回到来源 URL、抓取时间与原始快照。
- **资产可复用**：一次采集，多次查询；支持增量更新而不是重复劳动。
- **归因有边界**：区分相关与因果；数据不足时明确拒绝因果断言，并说明假设与局限。

### 2.5 非目标（当前）

- 不做无差别全网爬取，不绕过登录、验证码、付费墙或访问控制。
- 不提供无证据的因果结论；不用“相关”包装成“因果”。
- 不替代专业统计建模与法律合规审查。
- 首版不做图形化工作台与多租户 SaaS。

以上边界待确认。

## 3. 产品流程

```text
模糊需求
  → 意图澄清（目标、对象、口径、时间范围、预算）
  → 采集计划（种子、字段 schema、深度、并发、停止条件、合规约束）
  → 发现与并发采集（搜索、链接扩展、抓取、快照）
  → 抽取与归一（实体、事件、关系、去重、冲突处理）
  → 数据资产（版本化存储、查询、增量）
  → 分析与事件归因（统计、证据链、因果假设与置信度）
  → 交付（报告、表格、数据集、接口）
  ↺ 结论与人工反馈回流到口径和资产
```

**事件逻辑归因**在本产品中的定义：

> 从采集到的事件与实体中，识别结果事件（例如“某类岗位薪资更高”“某类背景更容易获得面试”），
> 给出候选条件、证据链、替代解释与置信度；在数据条件允许时使用因果方法，
> 否则明确标注为相关性结论。

## 5. 用户场景

### 场景 A：岗位条件归因

- **输入**：目标岗位（如“AI 应用工程师”）、城市、经验级别、时间范围。
- **澄清**：确认行业范围、全职/实习、薪资口径、是否包含远程岗位。
- **采集**：招聘站点与公司官网的岗位描述、技能要求、薪资、发布时间。
- **分析**：技能出现频率、技能组合、薪资分布、经验与学历门槛。
- **归因**：哪些条件与更高薪资或更高面试转化相关；在数据允许时进一步做因果分析。
- **输出**：岗位能力画像、条件优先级、证据来源、置信度与数据局限。

成功标准待补充（覆盖率、抽取准确率、结论可执行性）。

### 场景 B：模糊需求的海量采集

- **输入**：例如“帮我看看新能源车企最近的招聘趋势”。
- **澄清**：行业边界、公司清单、时间窗口、关注字段、交付形式。
- **计划**：种子查询、目标站点、抓取深度、并发与频率、预算、停止条件。
- **采集与沉淀**：并发抓取、抽取归一、去重后写入数据资产。
- **输出**：可查询数据集 + 趋势报告；后续问题可复用资产。

成功标准待补充（页面规模、并发峰值、单位成本、报告时效）。

### 场景 C：资产复用与增量更新

- **输入**：在已有资产上提出新问题，或要求刷新旧数据。
- **流程**：先查询资产判断覆盖度，只对缺口做增量采集；记录资产版本。
- **输出**：沿用同一口径的新结论，附版本与差异说明。

## 7. 非功能需求

- **NFR-1 合规与伦理**：遵守 robots.txt、服务条款与访问频率限制；不绕过访问控制；最小化个人数据。
- **NFR-2 规模**：单任务页面规模、峰值并发、日均吞吐目标待补充。
- **NFR-3 可靠性**：失败重试、断点续采、任务可恢复；单站点或单页失败不影响整体。
- **NFR-4 数据质量**：schema 校验、抽取准确率/召回率、去重率、字段完整率目标待补充。
- **NFR-5 可追溯**：任何结论可定位到来源页面、抓取时间与快照哈希。
- **NFR-6 可复现**：同一输入与版本应能得到相同或可解释差异的结果。
- **NFR-7 成本可控**：每个任务有页面数、并发、模型调用与存储预算。
- **NFR-8 安全**：密钥只从环境变量读取；不记录敏感凭据；工具调用受策略约束。
- **NFR-9 可扩展**：新数据源、抽取器、分析方法和报告模板通过插件/接缝扩展。
- **NFR-10 兼容性**：Node.js >= 20.19；沿用现有 npm workspaces 结构。

## 8. 约束与依赖

- 框架：`@deepseek-ai/cordis` 4.0.6-alpha.1（DeepSeek Harness vendored fork）。
- 模型：DeepSeek；搜索：Tavily（按需配置）。
- 现有代码只提供最小运行时，采集、抽取、资产、归因、报告均需新增包与接缝。
- 当前限制：会话仅内存；无持久化、压缩、恢复；无沙箱、审批、配额与遥测。
- 数据源许可与抓取权限需逐站点确认。

## 10. 风险与开放问题

- **合规风险**：目标站点的 robots.txt、ToS、数据许可与个人信息保护；需要逐源策略。
- **因果有效性**：网页观察数据存在选择偏差、混杂因素与缺失；因果结论必须附假设与敏感性分析。
- **抽取可靠性**：LLM 抽取可能幻觉或漏抽；需要 schema 校验、抽样复核与评测集。
- **数据偏差**：招聘站覆盖不等于真实市场；需要说明样本来源与偏差。
- **成本与规模**：海量并发抓取与模型调用可能成本失控；需要预算与停止条件。
- **新鲜度**：页面变化与失效需要变更检测与快照策略。
- **产品边界**：先做哪个垂直领域、资产以什么形式交付、是否对外提供接口，均待确认。
